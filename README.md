# 🛡️ Secure Gemini Code Packer (Strict Audited Edition)

ローカルのプロジェクトフォルダやZIPアーカイブを、**外部サーバーへ一切送信せずブラウザ内（クライアントサイド）のメモリ処理のみで解析**し、Geminiなどの大規模言語モデル（LLM）に最適な単一のMarkdownファイル（ディレクトリツリー＋各ソースコード）へ変換するWebアプリケーションです。

外部CDNやサードパーティ製ライブラリへの依存を完全に排除（Zero External Dependencies）し、厳格なContent Security Policy（Strict CSP）と多層防御アーキテクチャによって設計されています。

---

## ✨ 主な特徴

* **100% クライアントサイド処理 & Strict CSP**
  * 外部スクリプトや外部通信を一切行いません（`default-src 'none'; script-src 'self'; connect-src 'none'`）。
  * すべての解析処理は同一オリジン内の専用 `Web Worker` 上で実行されます。
* **外部ライブラリ非依存の厳格なネイティブZIPパーサー**
  * ブラウザ標準の `DecompressionStream('deflate-raw')` と独自のバイナリ検証器により、サードパーティ製ZIPライブラリを介さずにインメモリで展開します。
  * EOCD（終端レコード）境界検証、Central Directoryとローカルファイルヘッダ（LFH）の完全一致確認、エントリ領域の重複（Overlap）遮断、および **IEEE 802.3 CRC-32 完全照合** を行います。
* **多層防御によるリソース保護（Zip Bomb / DoS対策）**
  * ヘッダサイズを偽装した圧縮爆弾（Zip Bomb）に対しても、ストリームのチャンク読み取り段階で実展開サイズを監視し、上限を超えた瞬間にストリームを即時破棄します。
  * フォルダ走査・Worker解析の双方で `AbortController` とタイムアウト監視が機能し、いつでも即座にキャンセルとメモリ解放が可能です。
* **機密情報の二段階フィルタリング＆出力前プレビュー**
  * **ファイル名検査**: `.env`、秘密鍵（`.pem`, `.key`, `id_rsa` 等）、認証情報ファイルを自動除外。
  * **本文コンテンツ検査**: AWSアクセスキー、GitHub/Slack/OpenAIトークン、Google APIキー、JWT、DB接続URI、`Authorization: Bearer`、引用符なしのパスワード/APIキー代入式などを検出し、**デフォルトでファイルごと安全に除外**（または `[REDACTED]` マスクを選択可能）します。
  * **出力前レビュー機構**: 生成されたMarkdownのプレビューを画面上で確認し、確認チェックボックスをONにして初めてコピー・ダウンロードが有効化されます。
* **Markdown破壊＆プロンプトインジェクション対策**
  * CommonMark仕様に準拠した動的コードフェンス（4連以上のバッククォート自動拡張）およびインラインコードスパン保護により、特殊文字を含むファイル名やコードでも構造が崩れません。
  * LLMがコード内の悪意あるコメントをシステム命令として誤認するのを防ぐ「未信頼データ境界宣言（Untrusted Data Boundary）」を自動付与します。
* **内蔵セキュリティ自己診断スイート（全12項目）**
  * 実ブラウザ上で攻撃用・異常系テストデータ（Zip Slip、CRC改ざん、LFH矛盾、ヘッダ偽装Deflate爆弾、引用符なし秘密情報、`__proto__` 汚染など）を動的合成し、防御機構が正常に機能するかをワンクリックで自己検証できます。

  ├── 📄 index.html   # アプリケーションUI & Strict CSP定義

## 🚀 使い方

### 1. Webアプリ（GitHub Pages）で利用する場合
1. 公開されている GitHub Pages のURLにアクセスします。
2. 画面中央のドロップゾーンに **プロジェクトフォルダ** または **`.zip` ファイル** をドラッグ＆ドロップします（または選択ボタンから指定）。
3. 解析完了後、下部の **「出力前プレビュー＆機密監査確認」** で内容と除外ログを確認します。
4. **「出力内容に機密情報が含まれていないことを確認しました」** にチェックを入れ、**「📋 コピー」** または **「💾 Markdown保存」** を実行します。

### 2. ローカル環境で動かす場合
Strict CSP および Web Worker（`new Worker('./worker.js')`）の同一オリジン制約により、`file://` プロトコル（HTMLファイルの直接ダブルクリック）ではWorkerが起動しません。以下のいずれかの方法でローカルHTTPサーバーを起動してアクセスしてください。

**Python を使用する場合:**
```bash
python3 -m http.server 8000
# ブラウザで http://localhost:8000 を開く
```

**Node.js を使用する場合:**
```bash
npx serve .
```

## 🔒 セキュリティ制限仕様（デフォルト値）

ブラウザのメモリ枯渇（OOM）やフリーズを防ぐため、`worker.js` および `app.js` で以下のクォータ制限を設けています。

| 制限項目 | 上限値 | 備考 |
| :--- | :--- | :--- |
| **総走査エントリ数** | **10,000 件** | スキップ・除外対象を含む最大走査数 |
| **最大採用ファイル数** | **2,000 件** | Markdownに出力される有効ファイルの最大数 |
| **単一ファイル展開上限** | **1 MB** | 1ファイルあたりの最大バイト数（ストリーム監視） |
| **累積展開バジェット** | **25 MB** | 全ファイルの展開バイト数合計の上限 |
| **最終Markdown文字数** | **20 MB相当** | 出力文字列の最大長制限 |
| **最大ディレクトリ階層** | **25 階層** | 深すぎる階層・循環構造の遮断 |
| **処理タイムアウト** | **30 秒** | Worker処理（フォルダ走査は20秒）の最大許容時間 |

## 🧪 セキュリティ自己診断（Self-Test）の検証項目

画面上の **「🧪 厳格セキュリティ自己診断 (12項目)」** ボタンを押すと、以下の12項目が実ブラウザ上で自動テストされます。

1. **Central Directory 境界逸脱（EOCD侵食）の拒否**
2. **ローカルヘッダ（LFH）と Central Directory の属性不整合の拒否**
3. **エントリ領域重複（Overlap）アーカイブの拒否**
4. **CRC-32 不一致（改ざん・破損データ）の検証と拒否**
5. **ヘッダサイズ偽装型 Deflate Zip Bomb の実展開ストリーム遮断**
6. **Zip Slip（`../../`）パストラバーサル遮断**
7. **引用符なし秘密情報（`password = ...`, `API_KEY=...`, `Bearer`）の検出・マスク**
8. **機密ファイル名（`.env.local` 等）のブラックリスト除外**
9. **`__proto__` / `constructor` 等の特殊ディレクトリ・ファイル名耐性（Map/Set構築）**
10. **バッククォートを含むファイル名の CommonMark コードスパン保護**
11. **本文内3連バッククォートに対する動的4連コードフェンス生成**
12. **総展開バジェット上限到達時の安全停止 ＆ キャンセル時の待機Promise即時決済**

## ⚠️ 免責事項・ご利用上の注意

* **秘密情報検出の限界について**: 本ツールの機密情報検出は、ファイル名および正規表現パターン（既知のトークン形式や典型的な変数代入）に基づくヒューリスティック検査です。独自形式のシークレット、難読化された認証情報、複数行に分割された鍵など、**すべての秘密情報の完全な検出・除外を保証するものではありません**。
* **最終確認の徹底**: 生成されたMarkdownを外部のAIサービス（Gemini等）へ送信する前に、必ず利用者自身の責任においてプレビュー内容を確認し、機密情報や社外秘コードが含まれていないことを点検してください。
* **HTTPヘッダによる追加保護**: GitHub Pages 等のホスティング環境以外（自社サーバー等）で運用する場合は、メタタグCSPに加えてHTTPレスポンスヘッダで `Content-Security-Policy: frame-ancestors 'none'` や `X-Content-Type-Options: nosniff` を付与することを推奨します。
